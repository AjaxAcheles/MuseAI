# Task G — stop a collapsed rewrite from scoring as an improvement

Repo: MuseAI (Python 3.12, LangGraph FSM). Read `AGENTS.md` first and obey it:
config-driven never hardcoded, no stubs, no speculative config keys, deliver
complete files not diffs, tests are `pytest` named `test_*.py`, follow the
existing code style and comment voice in every file you touch.

## The bug (observed live, 2026-08-21)

On beat 1 of a real run, a full-mode rewrite collapsed the beat from **988 words
to 150**, and the FSM scored that as progress:

- `museai/fsm/nodes/critics.py` computes `improved = best_count is None or
  total < best_count` purely over the *count of findings*. `total_failures` fell
  5 -> 4, so `improved=True` and the 150-word stub became `best_seen_draft` /
  `best_seen_failure_count` / `best_seen_failures`.
- The next `revise_prose` then worked from the stub (212 words out), and the
  best-seen rollback in `revise_prose` — which exists to protect quality — was
  now protecting the collapsed version.
- `progressed_by_signature` was `True` on the same cycle, because a collapse
  changes every quoted `offending_text`, so all prior signatures disappear.

Root cause: both progress rules are computed over the *set of findings*, never
over the prose itself. Fewer words give the critic less surface to fault, so
deleting prose is a monotonic way to win on both rules at once. There is no
word-count floor anywhere in `revise.py` or `audit.py`, and
`generation.word_count_target` is `null`.

This is a scoring-design bug, not a model bug. Fixing only one half leaves the
hole open, so implement **both** parts below.

## Part 1 — a length floor on full rewrites (`museai/fsm/nodes/revise.py`)

In `revise_prose`, the `if not span_mode:` branch currently does:

```python
    if not span_mode:
        messages, collapsed = _budgeted_messages(
            config,
            mode="full",
            draft_text=draft,
            failures=failures,
            span_text="",
            package=package,
        )
        revised = await _rewrite(config, messages, f"beat {beat_id!r}", beat_id)
```

Add a bounded retry around that `_rewrite`, mirroring the existing
`span_rejection_retries` loop directly above it (same shape, same logging
style):

- After each `_rewrite`, compare `len(revised.split())` against
  `len(draft.split())`. Reject when the rewrite falls below
  `config.revision.full_rewrite_min_word_ratio * len(draft.split())`.
- On rejection, log `log_node_event("revise", event="rewrite_too_short",
  beat_id=beat_id, attempt=..., words=..., baseline_words=..., floor=...)` and
  retry with a correction turn appended to `messages`, exactly the way the span
  loop appends `{"role": "assistant", ...}` then
  `{"role": "user", "content": _SPAN_REJECTION_CORRECTION.format(...)}`.
  Add a module-level `_SHORT_REWRITE_CORRECTION` constant next to
  `_SPAN_REJECTION_CORRECTION`, in the same voice: tell the model the rewrite
  dropped from N words to M, that it must fix the named failures **without
  cutting the beat's events, scenes or dialogue**, and that it should return
  prose of comparable length.
- Budget the retries with `config.revision.full_rewrite_retries`.
- If every attempt is still below the floor, **keep the pre-rewrite `draft`**
  (do not splice the collapsed text in) and log
  `log_node_event("revise", event="rewrite_collapse_abandoned", beat_id=beat_id,
  words=..., baseline_words=...)`. Returning the original draft unchanged is the
  honest outcome: the beat then fails the router's progress rule and parks for
  review, which is correct, and is strictly better than committing a stub.
  Make sure the `event="revised"` log line and the `bus.publish("revision", ...)`
  payload still fire with the draft that is actually being returned.

Note the existing `replacement_rejection` guard is span-only and stays as it is;
this is the full-mode counterpart.

## Part 2 — length-aware best-seen scoring (`museai/fsm/nodes/critics.py`)

Around line 632:

```python
    combined = [*state["critic_failures"], *failures]
    total = len(combined)
    best_count = state["best_seen_failure_count"]
    improved = best_count is None or total < best_count
```

A draft substantially shorter than the running best must not be able to claim
`improved` on failure count alone. Gate it: when `state["best_seen_draft"]` is
not None and `len(draft.split())` is below
`config.revision.best_seen_min_word_ratio * len(best_seen_draft.split())`, then
`improved` is `False` regardless of `total`, so `best_seen_draft`,
`best_seen_failure_count` and `best_seen_failures` all keep their existing
values.

Log the suppression so a run is debuggable — add a
`best_seen_rejected_short=True/False` field (or an equivalently named field
consistent with the surrounding log vocabulary) to the existing
`log_node_event("critics", event="critiqued", ...)` call rather than emitting a
separate event.

Leave `progressed` / `progressed_by_signature` and the `last_cycle_improved`
semantics alone — Part 1 is what stops a collapse from ever reaching this node,
and Part 2 is the backstop that keeps one from being latched as best-seen.
Resolve the config access the same way the surrounding code in `critics.py`
already reaches config (do not import a new global).

## Part 3 — config

Add exactly three keys to `RevisionConfig` in `museai/core/config.py`, with
comments in the established voice explaining the measurement that motivated
them (the 988 -> 150 collapse), plus validators consistent with the ones already
there:

- `full_rewrite_min_word_ratio: float = 0.6` — proportion in 0..1, validated.
- `best_seen_min_word_ratio: float = 0.75` — proportion in 0..1, validated.
- `full_rewrite_retries: int = 1` — must be `>= 0`, validated.

Add all three to the `revision:` block of **both** `config.yaml` and
`config.example.yaml` (config.yaml's `revision:` block starts at line 434), with
the same commentary style as the `span_rejection_retries` entry there.

Config is `extra='forbid'`, so a key present in one file and missing from the
model is fatal at boot — keep the model and both YAML files in sync.

## Part 4 — tests

Add tests to the existing `tests/test_revise.py` and `tests/test_critic_resilience.py`
(follow their existing fixtures — `state_with`, `failure`, `patched_llm`,
`config_factory` in `tests/conftest.py`). Cover at least:

1. A full rewrite returning far too few words is retried, and the retry's
   corrected output is accepted when it clears the floor.
2. A full rewrite that stays below the floor for every attempt leaves the
   returned prose equal to the pre-rewrite draft, and emits
   `rewrite_collapse_abandoned`.
3. A rewrite comfortably above the floor is untouched — no extra LLM call.
4. In `critics`, a draft below `best_seen_min_word_ratio` of `best_seen_draft`
   with a *lower* failure count does NOT become `best_seen_draft`.
5. In `critics`, a draft of comparable length with a lower failure count still
   does become `best_seen_draft` (guard against over-blocking).
