## Why

An external review of the working tree found two defects in
`museai/fsm/nodes/audit.py`. Both are confirmed by measurement.

### Defect 1 — `phrase_echoes` takes `max_words` and never uses it

`phrase_echoes` (line ~198) declares `max_words: int` in its signature, and both
call sites pass `max_words=config.tools.repetition_phrase_max_words`. The
parameter is never referenced in the body. Verified directly: a 12-word shared
run is flagged identically with `max_words` set to 1, 5, 12 and 100.

So a documented config key appears to tune this audit and does nothing. This
codebase treats `config.yaml` as the single tuning surface, so a knob that lies
is a real defect even though no duplication is currently missed.

**Resolve it by removing the parameter, not by enforcing it.** The audit should
have only a *minimum*: a verbatim run of `min_words` or more is an echo, and a
longer run is worse, not exempt. The live bug this guard exists for was a
**40-word** copy — capping at `repetition_phrase_max_words` (12) would have to
either still flag it (making the cap meaningless here) or skip it (reintroducing
the bug). A maximum has no coherent meaning for this check.

`repetition_phrase_max_words` keeps its real job: bounding the *model-supplied*
query phrase in `find_repetition` / `verbatim_phrase_matches`. Leave that alone.

### Defect 2 — the previous task reintroduced a whole-corpus rescan

`phrase_echoes` was previously optimized to normalize the corpus once and use
substring matching; that was measured at **0.351 s** for a 3-paragraph draft
against 90,000 committed words. The sanitization task then rewrote its body to
call `longest_shared_verbatim_word_run` (line ~223) and, at line ~224, to strip
the pre-normalized text back out:

```python
if longest_shared_verbatim_word_run(
    paragraph, [passage for passage, _ in corpus]
) >= min_words:
```

That discards the memoized normalization *and* replaces a substring scan with an
O(draft_words x corpus_words) dynamic-programming matrix, re-normalizing every
passage for every draft paragraph. Measured now:

| draft paragraph words | committed words | seconds |
|---|---|---|
| 100 | 36,000 | 0.073 |
| 100 | 90,000 | 0.182 |
| 300 | 90,000 | 0.512 |
| 500 | 90,000 | **0.838** |

`audit` runs after drafting and after every revision, synchronously inside an
async FSM node, so this blocks the event loop.

## What to change — `museai/fsm/nodes/audit.py`

- **Remove `max_words` from `phrase_echoes`'s signature** and from both call
  sites (`audit`, and `museai/fsm/tools/check_draft.py`). Update its docstring to
  state plainly that the check has a minimum run length and no maximum.
- **Replace the DP call with a bounded n-gram membership test.** Any verbatim run
  of `min_words` or more necessarily contains at least one contiguous
  `min_words`-length n-gram, so exact-length n-grams are sufficient for
  *detection* and need no matrix:
  - normalize each corpus paragraph once, split to words, and collect every
    contiguous `min_words`-length word tuple into a `set`;
  - for each draft paragraph, test its own `min_words`-length n-grams against
    that set;
  - build the corpus n-gram set incrementally as earlier draft paragraphs join
    the corpus, preserving today's behaviour where a paragraph is compared
    against committed prose **and** against earlier paragraphs of the same draft.
- Keep `longest_shared_verbatim_word_run` exactly as it is. The sanitization path
  in `critics.py` legitimately needs the longest-run *count* (it logs the number
  of borrowed words) and compares one short `suggested_fix` against a small
  recent-prose window. Do not change it or its callers.
- Detection semantics must not change: the same paragraphs are flagged, the
  allowlist and `intended_refrain` suppression behave identically, and the
  `phrase_echoes=` count on the `audited` log event still reports the same value.

