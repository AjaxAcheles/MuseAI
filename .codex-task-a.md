## Fix 1 — saving settings from the web UI destroys every comment in config.yaml

### The bug

`museai/web/routes/settings.py`, in `save()` (around line 171):

```python
persisted = validated.model_dump()
if keep_existing_key:
    raw_key = _raw_api_key_on_disk(path)
    if raw_key:
        persisted["endpoint"]["api_key"] = raw_key
path.write_text(yaml.safe_dump(persisted, sort_keys=False), encoding="utf-8")
```

`yaml.safe_dump` serialises a plain dict, so the written file has no comments.
The settings page embeds the whole config as JSON in `data-config` and posts
**all** of it back on every save (`museai/web/static/js/main.js`), so one click
of Save rewrites the entire file and strips every comment in it.

This is not hypothetical. `config.yaml` carries 181 comment lines that document
why each threshold has the value it has — the Ollama context-window trap, why
the critic's `max_output_tokens` and `output_reservation` must move together,
why the reviser needs `reasoning_effort: none`. A single Save destroyed all of
them once already and they had to be restored by hand from git. The file's
comments are the operational knowledge for tuning this system; losing them is a
real data loss, not cosmetics.

### The fix

`ruamel.yaml` is **already installed and already declared** in `pyproject.toml`
(`ruamel.yaml`, resolved to `ruamel-yaml==0.19.1`). Do not add it again and do
not try to install anything — the sandbox has no network.

Rewrite the persistence step in `save()` to round-trip through `ruamel.yaml` so
comments, key order, and formatting on disk survive:

- Load the **existing** `config.yaml` with `ruamel.yaml.YAML()` (round-trip
  mode, which is the default) and `preserve_quotes = True`. That gives a
  `CommentedMap` that carries every comment as attached metadata.
- Walk the validated config dict and write its values **into** that loaded
  `CommentedMap` in place, recursively:
  - When both the existing node and the new value are mappings, recurse so the
    comments on the inner keys survive too.
  - When a key exists on disk, assign the new value to it (this preserves the
    comment attached to that key).
  - When a key is new (present in the validated config but not on disk), add it.
  - When a key is on disk but absent from the validated config, remove it —
    the validated `AppConfig` is the authority on what keys exist, and leaving a
    stale key behind would be fatal at the next boot under `extra='forbid'`.
- Dump back to the file.

Verified working against ruamel 0.19.1 — this exact shape round-trips a
top-comment, an inline comment, and a nested key without loss:

```python
from ruamel.yaml import YAML
yaml_rt = YAML()
yaml_rt.preserve_quotes = True
data = yaml_rt.load(path.read_text(encoding="utf-8"))
# ... merge ...
with path.open("w", encoding="utf-8") as handle:
    yaml_rt.dump(data, handle)
```

Requirements and edge cases you must handle:

1. **First-ever save with no config.yaml on disk**, or a file that is empty or
   does not parse as a mapping. There is no document to preserve, so fall back
   to writing the config fresh. Keep this path working — do not let a missing
   file raise.
2. **The API key must keep its `${VAR}` form.** The existing
   `_raw_api_key_on_disk` / `keep_existing_key` logic already handles this and
   must keep working unchanged: the in-memory config holds the *resolved*
   secret, and writing that to disk would leak the plaintext secret and destroy
   the env reference. Do not regress this. Note that with a round-trip merge the
   on-disk `${MUSEAI_API_KEY}` string is now also what is already in the loaded
   document — but keep the explicit logic, because the value being assigned
   comes from the validated dict.
3. **Lists** (e.g. `endpoint.retry_backoff_seconds`, and the optional
   `repetition_allowlist` / `emotion_words` / `tic_phrases`) must be assigned
   whole. Do not try to merge lists element-by-element.
4. **`None` values must serialise as an empty/`null` scalar that reloads as
   `None`**, e.g. `max_output_tokens: null`. Check what ruamel emits and make
   sure a save→reload round-trip is stable.
5. The existing behaviour after writing — `load_config(path)`, `init_resources`,
   `set_runtime`, and returning `{"ok": True, "settings": ...}` — stays exactly
   as it is.
6. `yaml.safe_load` in `_raw_api_key_on_disk` is fine as-is; that function only
   reads one string and does not write. Leave it alone.

Put the merge helper in `museai/web/routes/settings.py` as a module-level
private function with a docstring that explains *why* it exists (comment
preservation), not just what it does.

## Fix 2 — layering inversion: the LLM seam imports from an FSM node

`museai/llm/structured.py` line 37 does:

```python
from museai.fsm.nodes.audit import split_sentences
```

used at line ~555 inside `is_clean_verdict`. `museai/llm/` is the
endpoint-agnostic LLM adapter seam; `museai/fsm/nodes/` sits above it. This is
an inward dependency from a lower layer to a higher one. There is no import
cycle today, so nothing is broken — but it is the wrong direction and the next
import added to `audit.py` could make it a cycle.

### The fix

Create `museai/core/text.py` — a small, dependency-free module of
sentence-segmentation helpers — and move these three things into it **verbatim,
behaviour unchanged**, from `museai/fsm/nodes/audit.py`:

- `_SENTENCE_SPLIT` (the compiled regex, including its existing explanatory
  comment about abbreviations over-splitting)
- `sentence_spans(text) -> list[tuple[int, int]]`
- `split_sentences(text) -> list[str]`

Then:
- `museai/fsm/nodes/audit.py` imports `sentence_spans` and `split_sentences`
  from `museai.core.text` and keeps using them exactly as now. It must keep
  working for any caller that currently does
  `from museai.fsm.nodes.audit import split_sentences` — but see below, you
  should fix those callers rather than leave a re-export alias.
- `museai/llm/structured.py` imports `split_sentences` from `museai.core.text`.
- `museai/fsm/routers/mode_selector.py` imports `CRITIC_SOURCE` from
  `audit.py` — that one is fine and unrelated; leave it.

Search the whole repo (including `tests/`) for
`from museai.fsm.nodes.audit import` and update any import of
`split_sentences`, `sentence_spans`, or `_SENTENCE_SPLIT` to point at
`museai.core.text`. Do **not** leave a backwards-compatibility re-export in
`audit.py` — this is a private codebase with no external consumers, and a
re-export alias is exactly the kind of dead passthrough AGENTS.md forbids.

`museai/core/text.py` must not import from `museai.fsm` or `museai.llm`. Give it
a module docstring explaining what it is for and why it lives in `core` (shared
by the audit node and the LLM seam, so it cannot live in either).

Behaviour must be **identical**. The regex is
`r"(?<=[.!?])[\"')\]”’]*\s+"` — note the typographic closing quotes `”’`,
which are deliberate; copy it exactly, character for character.
