## Context

You (in a previous run) rewrote `save()` in `museai/web/routes/settings.py` to
round-trip `config.yaml` through `ruamel.yaml` so comments survive. That work is
correct in structure and the tests pass. But when it is run against the **real**
518-line `config.yaml`, it still loses 20 comment lines and grows the file from
518 to 562 lines.

I measured this directly. Two distinct causes.

### Cause 1 — unchanged values are reassigned, destroying their on-disk form

`_merge_validated_config` assigns **every** key, whether or not the value
changed:

```python
for key, value in validated.items():
    current = existing.get(key)
    if isinstance(current, CommentedMap) and isinstance(value, Mapping):
        _merge_validated_config(current, value)
    else:
        existing[key] = value          # <-- happens even when equal
```

Assigning replaces the round-trip node (which carries formatting and any
comments attached *inside* it) with a plain Python value. Observed damage on a
save that changed nothing but one unrelated key:

- `max_output_tokens: null` became `max_output_tokens:` — a bare value. It still
  reloads as `None`, but the explicit `null` is what the surrounding comment
  refers to ("Leave null.").
- `retry_backoff_seconds: [5.0, 15.0]` (flow style, one line) became a
  three-line block sequence.
- Every comment written *inside* a list was destroyed. `generation.emotion_words`
  is a 115-entry list grouped by category with `# fear`, `# anger`, `# sadness`,
  `# shame`, `# joy`, `# other named states` heading each group; `tic_phrases`
  is organised the same way. All of those group headings were lost, because the
  whole `CommentedSeq` was replaced by a plain `list`.

### Cause 2 — the sparse `agents:` block is exploded with nulls

`AgentEndpointOverride` has 15 optional fields and `model_dump()` emits all of
them. `config.yaml` deliberately sets only 2–4 per role, and the block's comment
explains that it is **sparse**: "only the keys named here differ for that agent,
everything else is inherited."

After one save, every role gains 11 explicit null keys:

```yaml
  chapter_planner:
    temperature: 0.4          # structural JSON: obligations and chapter shape
    output_reservation: 2048
    # Same measurement as the drafter and critic, extended to the planners on
    # 2026-08-19. ...
    reasoning_effort: none
    base_url:
    api_key:
    model_name:
    tokenizer_family:
    request_timeout:
    stream_read_timeout:
    max_output_tokens:
    extra_body:
    stream_usage:
    context_window:
    max_attempts:
    retry_backoff_seconds:
```

That is 55 added lines across the five roles. It is semantically harmless — a
`None` override means "inherit", which is exactly what an absent key means — but
it buries the block's documentation in noise and contradicts the comment
directly above it.

## The fix

Both causes, in `museai/web/routes/settings.py`.

### Fix 1 — only write a key whose value actually changed

In `_merge_validated_config`, skip the assignment when the existing value
already equals the new value. Only a genuine change should touch the document:

```python
elif key not in existing or existing[key] != value:
    existing[key] = value
```

This works for lists too: `CommentedSeq` subclasses `list`, so `==` compares by
content, and an unchanged list keeps its node — and therefore its interior
comments and its flow style.

Keep the existing recursion for nested mappings and keep the existing deletion
of keys absent from the validated config (a key the validated `AppConfig` does
not have must not survive on disk, or the next boot fails under
`extra='forbid'`).

Update the function's docstring to say *why* the equality check is there —
that reassigning an unchanged node discards its formatting and its interior
comments. Match the file's existing comment voice.

### Fix 2 — keep the agents block sparse

Before merging, drop `None`-valued keys from each per-agent override in the
dumped config, so a save writes only the overrides that are actually set.

This is safe and lossless: in `AgentEndpointOverride` every field is optional and
`None` means "inherit from the top-level `endpoint`", which is exactly what an
absent key means. Confirm that for yourself in `museai/core/config.py` before
you write it.

It must still be possible to **clear** an override from the UI: if the user
blanks a field that is currently set on disk, the key becomes `None`, is dropped
here, and is then deleted from the document by the existing "keys absent from
validated" rule in `_merge_validated_config`. Verify that path works — it is the
one that could silently break.

Do this only for `agents`, not for the rest of the config: elsewhere, `None` is
a meaningful configured value (`generation.word_count_target: null`,
`endpoint.max_output_tokens: null`) and its key must stay on disk with its
explanatory comment.
